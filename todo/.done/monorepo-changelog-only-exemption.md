# Monorepo: changelog-only commit exemption doesn't work

## Problem

In a monorepo, commits that only touch `.rlsbl/changes/` files inside a sub-project (e.g., `python/.rlsbl/changes/unreleased.jsonl`) are NOT exempted from coverage checks. The exemption logic likely checks for `.rlsbl/changes/` at the start of the path, but in a monorepo the path is prefixed with the sub-project directory.

This creates a chicken-and-egg loop: every changelog commit creates a new uncovered commit that needs its own changelog entry, which creates another uncovered commit, ad infinitum.

## Reproduction

```bash
cd ~/Projects/strictcli/python
safegit commit -m "changelog: cover commits" -- python/.rlsbl/changes/unreleased.jsonl
rlsbl changelog validate
# FAIL: the commit above is not exempted, not covered
```

The `rlsbl changelog add` auto-commits ARE exempted (as "autogenerated"), but manual commits touching only `.rlsbl/changes/` files are not.

## Expected behavior

Commits that only modify files under `{subdir}/.rlsbl/changes/` or `{subdir}/CHANGELOG.md` should be exempted, same as commits modifying `.rlsbl/changes/` in a non-monorepo.

## Impact

Blocks releases for monorepo sub-projects. The only workaround is to use `rlsbl changelog add` (with auto-commit) for every coverage gap, but `.validated` cache changes still require manual commits that aren't exempted.
