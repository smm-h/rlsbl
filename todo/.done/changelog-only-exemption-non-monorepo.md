# Changelog-only commit exemption fails for manual commits in non-monorepo

## Problem

In a non-monorepo project, commits that only touch `.rlsbl/changes/unreleased.jsonl` are NOT auto-exempted from coverage checks when they were made manually (e.g., via `safegit commit` or `git commit`). Only commits created by `rlsbl changelog add` (auto-commits) are exempted as "autogenerated."

This creates a bootstrap loop: adding a `--no-user-facing` entry for the last uncovered commit creates a new commit that itself needs coverage, ad infinitum.

## Reproduction

In `/home/m/Projects/saferm/` (non-monorepo, single Go target):

- 16 commits exist that only touch `.rlsbl/changes/` files
- `rlsbl changelog validate` reports "skipped 6 autogenerated commit(s)" but flags 1 as uncovered
- The uncovered commit (`c3c0af9`) only modifies `.rlsbl/changes/unreleased.jsonl`
- The 6 skipped commits are the ones created by `rlsbl changelog add --no-commit` or that only touch `.validated`
- The 10 others were manually committed (by AI subagents using `safegit commit`) and needed explicit `--no-user-facing` entries to pass coverage

## Expected behavior

Per the docs: "Commits that only touch `.rlsbl/changes/` or `CHANGELOG.md` are automatically exempted." This should apply regardless of whether the commit was created by `rlsbl changelog add` or manually.

## Root cause (suspected)

The "autogenerated" detection likely checks commit message patterns or internal markers rather than simply checking which files the commit touches. It should check file paths only.

## Impact

Blocks releases. The workaround is to use `rlsbl changelog add --no-commit` and bundle the JSONL change with a non-changelog file in a single commit, but this is fragile and non-obvious.
