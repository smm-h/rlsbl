# Move pre-release checks from hook template into release command

Status: Proposed
Priority: High

## Problem

Pre-release checks (run tests, lint) are distributed as a hook template (.rlsbl/hooks/pre-release.sh.tpl) that's generated by scaffold. This means:

1. Existing projects don't get new checks until they run `scaffold --update`
2. The hook is user-owned — scaffold never overwrites it, so improvements don't propagate
3. Built-in behavior (language detection, test running, lint) is mixed with the user customization point
4. The template contains shell logic that duplicates what rlsbl could do natively in Python

## Proposed solution

Move built-in pre-release checks into `rlsbl release` directly:

1. **Language detection**: rlsbl already detects targets (pyproject.toml, package.json, go.mod). Use the same detection to run appropriate test commands.
2. **Test running**: `uv run pytest` for Python, `go test ./...` for Go, `npm test` for npm — run these as built-in steps before the version bump.
3. **Library lint**: `doctor --check library-lint` runs as a built-in step (already in rlsbl).
4. **User hook**: The `.rlsbl/hooks/pre-release.sh` becomes purely for user-defined custom checks. Users only write what's specific to their project.

The release flow becomes: built-in checks (tests + lint) → user hook (custom checks) → version bump → tag → push → release.

## Migration

- New projects: scaffold generates a minimal pre-release.sh (just a comment explaining it's for custom checks)
- Existing projects: the hook still works as-is. Built-in checks run in addition to (before) the hook. No breakage.
- Users who customized the hook: their custom checks still run. The duplicated test commands in the hook are redundant but harmless (tests run twice, which is wasteful but not broken). Document how to slim down the hook.

## Effort

Medium. The test-running logic exists in the hook template — needs to be ported to Python and integrated into release.py.
